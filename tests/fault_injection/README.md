# 设备错误与缓冲异常故障注入测试 (200 轮)

对音频设备生命周期和环形缓冲做确定性故障注入，覆盖 5 类故障并交替执行：

| 故障 | 触发操作 | 语义 |
|------|----------|------|
| `OPEN_FAIL` | `RESET/OPEN` | 设备打开失败（分配前拒绝） |
| `CB_TIMEOUT` | `TICK` | 音频回调错过截止时间（硬故障） |
| `UNDERRUN` | `TICK` | 消费者请求帧数超过队列（欠载，软故障） |
| `OVERRUN` | `PLAY` | 生产帧数超过容量（过载，丢弃多余帧） |
| `HOTPLUG` | `HOTPLUG` | 设备热拔出，需重新获取 |

每轮固定为：`RESET`（恢复基线）→ 注入故障的触发操作 → 0~2 个良性 `PLAY/TICK`
→ `RESET`（恢复边界）→ `CLOSE`。故障种类按轮次对 5 取模严格交替，
随机数使用固定种子的 xorshift，因此整个运行完全可复现。

## 三条硬性不变量

1. **零崩溃**：所有操作包在异常护栏内；同时由 ASan/UBSan 在工具层兜底。
2. **零泄漏**：每一步检查存活设备分配数只能是 0 或 1，并在每个恢复边界
   比较同程序点的存活数是否增长（能抓住“析构时才释放”所掩盖的跨轮泄漏）。
3. **状态可恢复**：每个故障之后的第一个干净 `RESET` 必须让 `is_usable()`
   重新为真；硬故障后管理器不得谎称设备仍可用，也不得吞掉失败。

## 文件

- `faulty_device.{h,cpp}` — 带环形缓冲的确定性设备模型与分配记账。
- `fault_injector.{h,cpp}` — 全局注入点 + 设备工厂，打开类故障在创建设备时
  消费，运行时故障直接挂到存活设备上。
- `robust_manager.{h,cpp}` — 被测的健壮实现（先释放再打开、故障即上报、
  热拔出有序拆除、超时即恢复）。
- `buggy_manager.{h,cpp}` — 故意植入三类缺陷的反例管理器。
- `test_harness.{h,cpp}` — 场景生成、不变量检查、ddmin 最小化。
- `main.cpp` — 入口，打印汇总并对失败序列做最小化。
- `soloud_stress.cpp` — 用真实 SoLoud（NULL 后端、同步 `mix()`）跑同样的
  200 轮压力，证明模型与真实引擎一致。

## 运行

```sh
cd tests/fault_injection
make all-tests      # 构建并运行全部
make test-robust    # 仅健壮管理器，严格 sanitizer（退出码必须为 0）
make stress         # 真实 SoLoud 引擎压力（退出码必须为 0）
make test           # 含反例的完整模型测试（退出码非 0 属预期）
```

可选参数：`--robust-only`（跳过反例）、`--no-shrink`（关闭 ddmin）、
`--seed=<n>`（更换随机交织，默认 `0xC0FFEE`；健壮管理器在任意种子下都通过）。

## 反例（buggy manager 植入的三类缺陷）

| 编号 | 缺陷 | 最小操作序列 | 观测到的违反 |
|------|------|--------------|--------------|
| B1 | `reset()` 不先 `close()` 就重开，旧设备指针被覆盖 | `RESET, HOTPLUG, RESET` | 恢复点存活设备 1→2，分配只增不减 |
| B2 | `is_usable()` 只看缓存标志，热拔出后仍报可用 | `RESET, HOTPLUG` | 硬故障后 `is_usable()` 仍为真 |
| B3 | 回调超时被当作成功返回 | `RESET, TICK+CB_TIMEOUT` | 硬故障被吞掉（`swallowed` 计数） |

健壮管理器在同一条最小序列上全部保持不变量；buggy 管理器则被准确捕获，
且失败序列经 ddmin 缩小到 2~3 条操作，即“失败时打印最小操作序列”。
